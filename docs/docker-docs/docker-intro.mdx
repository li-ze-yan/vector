## 概述

Docker 通过容器化技术将应用及其依赖打包为轻量级、可移植的镜像，让应用能够在任何支持 Docker 的环境中以一致的方式运行。

## Docker 的优势

### 环境一致性

容器封装了应用运行所需的全部依赖（运行时、库、配置），彻底消除 "在我机器上能跑" 的问题。无论是开发、测试还是生产环境，行为都保持一致。

### 轻量高效

相较于传统虚拟机，容器共享宿主机内核，不需要完整的操作系统，启动速度以秒计算，资源开销极小。同一台主机上可运行数十甚至上百个容器。

### 可移植性

镜像遵循 OCI 标准，可在任意 Linux / macOS / Windows 主机、以及各大云平台（AWS、GCP、Azure）上运行，无需修改。

### 快速交付与部署

结合 CI/CD 流水线，一次构建、多处部署。镜像不可变的特性让回滚变得简单，出问题时切换回上一个版本镜像即可。

### 隔离性

每个容器拥有独立的文件系统、网络和进程空间，多个应用在同一主机上互不干扰，提升了安全性和稳定性。

### 生态丰富

Docker Hub 提供海量官方与社区镜像（数据库、消息队列、语言运行时等），开箱即用，大幅降低环境搭建成本。

## 常用指令

### 镜像管理

```bash
docker pull <image>              # 从仓库拉取镜像
docker images                    # 查看本地镜像列表
docker rmi <image>               # 删除镜像
docker build -t <name>:<tag> .   # 基于 Dockerfile 构建镜像
docker tag <src> <target>        # 为镜像打标签
docker push <image>              # 推送镜像到仓库
```

### 容器生命周期

```bash
docker run -d --name <name> <image>   # 后台运行容器
docker run -it <image> /bin/bash      # 交互式运行
docker start <container>              # 启动已停止的容器
docker stop <container>               # 停止运行中的容器
docker restart <container>            # 重启容器
docker rm <container>                 # 删除容器（需先停止）
docker rm -f <container>              # 强制删除运行中的容器
```

### 容器查看与调试

```bash
docker ps                        # 查看运行中的容器
docker ps -a                     # 查看所有容器（含已停止）
docker logs -f <container>       # 实时查看容器日志
docker exec -it <container> sh   # 进入运行中的容器
docker inspect <container>       # 查看容器详细信息
docker stats                     # 实时查看资源占用
```

### 数据与网络

```bash
docker volume create <name>              # 创建数据卷
docker volume ls                         # 查看数据卷
docker run -v <volume>:/data <image>     # 挂载数据卷
docker run -p 8080:80 <image>            # 端口映射（主机:容器）
docker network create <name>             # 创建自定义网络
docker network connect <net> <container> # 容器加入网络
```

### Docker Compose

```bash
docker compose up -d        # 后台启动所有服务
docker compose down         # 停止并删除所有服务
docker compose logs -f      # 查看所有服务日志
docker compose ps           # 查看服务状态
docker compose build        # 构建或重建服务镜像
docker compose restart      # 重启所有服务
```

### 系统清理

```bash
docker system df            # 查看磁盘占用
docker system prune         # 清理未使用的容器、网络、镜像
docker system prune -a      # 清理所有未被使用的镜像
docker image prune          # 仅清理悬空镜像
```

## 免 sudo 执行 docker

即便当前账号是 sudoer，直接执行 `docker` 仍可能报：

```
permission denied while trying to connect to the docker API at unix:///var/run/docker.sock
```

原因：`docker` CLI 通过 `/var/run/docker.sock` 与 daemon 通讯，该 socket 默认属主 `root:docker`、权限 `0660`。只有 **`root` 或 `docker` 组成员**能直接调用，sudoer 身份与 `docker` 组成员身份是两码事。

把当前用户加入 `docker` 组即可：

```bash
sudo usermod -aG docker $USER
newgrp docker         # 或者退出重新登录 / 重开 SSH，使分组生效
getent group docker   # 确认用户已在组里
id -nG                # 查看当前会话的所属组包含 docker

docker ps             # 不再需要 sudo
```

### 安全提示

`docker` 组权限 ≈ root：组成员可通过将宿主机 `/` 挂载进容器实现本地提权。应严格控制能访问该账号的人员。如需更强隔离，可考虑 **rootless Docker** 或 **Podman**。

## 小结

Docker 以容器化标准化了应用的构建、分发与运行方式，是现代云原生架构的基石。掌握上述指令即可应对大部分日常开发与运维场景。
