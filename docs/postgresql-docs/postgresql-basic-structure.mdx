## 核心层级结构

PostgreSQL 的对象层级从高到低依次为：

```
PostgreSQL 实例（Cluster）
  └── 数据库（Database）
        └── 模式（Schema）
              └── 表 / 视图 / 函数 / 序列 等对象
```

- **Cluster（实例）**：一个运行中的 PostgreSQL 进程，监听一个端口，管理一组数据库。
- **Database（数据库）**：彼此完全隔离，跨库查询需借助 `dblink` 或 `postgres_fdw` 扩展。
- **Schema（模式）**：数据库内的命名空间，同一库下可有多个 Schema，默认为 `public`。
- **Table / View 等**：实际存储或逻辑呈现数据的对象，归属于某个 Schema。

## 为什么这么设计？

这种三层隔离（实例 → 库 → 模式）带来以下好处：

- **多租户隔离**：不同业务用不同数据库，权限天然隔离，互不干扰。
- **命名空间管理**：同一库内用 Schema 区分模块（如 `app`、`audit`、`legacy`），避免表名冲突。
- **权限细粒度**：可以把一个 Schema 的所有权授予特定角色，无需逐表授权。
- **逻辑解耦**：迁移或归档某个模块只需操作对应 Schema，不影响其他业务。

## 创建库、模式

### 创建数据库

```sql
-- 创建数据库，指定所有者和编码
CREATE DATABASE mydb
  OWNER = myuser
  ENCODING = 'UTF8'
  LC_COLLATE = 'en_US.UTF-8'
  LC_CTYPE = 'en_US.UTF-8'
  TEMPLATE = template0;

-- 切换数据库（psql 元指令）
\c mydb
```

### 创建模式

```sql
-- 在当前库下创建模式
CREATE SCHEMA app;
CREATE SCHEMA audit AUTHORIZATION myuser;  -- 指定所有者

-- 查看当前库所有模式
\dn

-- 设置搜索路径（优先在 app 下查找对象）
SET search_path TO app, public;

-- 删除模式（CASCADE 会连同内部对象一起删除）
DROP SCHEMA legacy CASCADE;
```

## pgsql 表操作

### 1. 创建表（CREATE TABLE）

```sql
CREATE TABLE app.users (
  id          BIGSERIAL       PRIMARY KEY,
  username    VARCHAR(50)     NOT NULL UNIQUE,
  email       TEXT            NOT NULL,
  age         SMALLINT        CHECK (age >= 0 AND age <= 150),
  status      VARCHAR(20)     NOT NULL DEFAULT 'active',
  created_at  TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

-- 常用约束速查
-- PRIMARY KEY    主键（唯一 + 非空）
-- UNIQUE         唯一约束
-- NOT NULL       非空
-- CHECK(expr)    自定义检查
-- DEFAULT value  默认值
-- REFERENCES     外键
```

### 2. 修改表（ALTER TABLE）

```sql
-- 添加列（无约束，存量数据自动填 NULL）
ALTER TABLE app.users ADD COLUMN avatar_url TEXT;

-- 添加列并指定默认值（存量行立即填充）
ALTER TABLE app.users ADD COLUMN score INT NOT NULL DEFAULT 0;

-- 删除列（CASCADE 同时删除依赖该列的视图/索引）
ALTER TABLE app.users DROP COLUMN avatar_url;
ALTER TABLE app.users DROP COLUMN avatar_url CASCADE;

-- 修改列类型（无歧义转换可直接改，否则需要 USING 指定转换表达式）
ALTER TABLE app.users ALTER COLUMN username TYPE VARCHAR(100);
ALTER TABLE app.users ALTER COLUMN age TYPE BIGINT USING age::BIGINT;

-- 设置 / 删除默认值（只影响之后的插入，不修改存量数据）
ALTER TABLE app.users ALTER COLUMN status SET DEFAULT 'inactive';
ALTER TABLE app.users ALTER COLUMN status DROP DEFAULT;

-- 添加 NOT NULL 约束到有存量数据的列（直接加会报错，需先补全 NULL 值）
UPDATE app.users SET phone = '' WHERE phone IS NULL;
ALTER TABLE app.users ALTER COLUMN phone SET NOT NULL;

-- 添加 / 删除唯一约束
ALTER TABLE app.users ADD CONSTRAINT uq_email UNIQUE (email);
ALTER TABLE app.users DROP CONSTRAINT uq_email;

-- 添加 / 删除 CHECK 约束
ALTER TABLE app.users ADD CONSTRAINT chk_age CHECK (age >= 0 AND age <= 150);
ALTER TABLE app.users DROP CONSTRAINT chk_age;

-- 添加外键
ALTER TABLE app.posts
  ADD CONSTRAINT fk_posts_user
  FOREIGN KEY (user_id) REFERENCES app.users(id) ON DELETE CASCADE;

-- 重命名列 / 表 / 约束
ALTER TABLE app.users RENAME COLUMN avatar_url TO profile_pic;
ALTER TABLE app.users RENAME TO members;
ALTER TABLE app.users RENAME CONSTRAINT uq_email TO uq_users_email;
```

**给有数据的表加 NOT NULL 的安全步骤：**

```sql
-- 1. 先加带默认值的可空列
ALTER TABLE app.users ADD COLUMN phone TEXT;

-- 2. 回填存量 NULL
UPDATE app.users SET phone = '' WHERE phone IS NULL;

-- 3. 再施加 NOT NULL（此时无 NULL 行，不会报错）
ALTER TABLE app.users ALTER COLUMN phone SET NOT NULL;
```

### 3. 删除表（DROP TABLE）

```sql
-- 删除单表
DROP TABLE app.users;

-- 表不存在时不报错
DROP TABLE IF EXISTS app.users;

-- 级联删除（同时删除依赖该表的视图、外键等）
DROP TABLE app.users CASCADE;
```

### 4. 清空表（TRUNCATE）

```sql
-- 快速清空，不写行级日志，比 DELETE 快得多
TRUNCATE TABLE app.users;

-- 同时重置自增序列
TRUNCATE TABLE app.users RESTART IDENTITY;

-- 级联清空（同时清空有外键依赖的子表）
TRUNCATE TABLE app.users CASCADE;
```

> `TRUNCATE` 与 `DELETE FROM` 的区别：`TRUNCATE` 直接回收数据页，不逐行记录 WAL，速度极快；但不能带 `WHERE` 条件，也不触发行级触发器。

### 5. 查看表信息（元指令与查询）

```sql
-- psql 元指令
\d             -- 列出当前 schema 下所有对象
\dt            -- 只列表
\dt app.*      -- 列出 app schema 下所有表
\d app.users   -- 查看 users 表结构（列、约束、索引）
\di            -- 列出索引
\df            -- 列出函数

-- 通过系统视图查询
SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_schema = 'app' AND table_name = 'users'
ORDER BY ordinal_position;

-- 查看表大小
SELECT pg_size_pretty(pg_total_relation_size('app.users'));
```

### 6. 特色操作：表继承（Inheritance）

PostgreSQL 支持表的面向对象继承，子表自动拥有父表的所有列。

```sql
-- 创建父表
CREATE TABLE vehicles (
  id      BIGSERIAL PRIMARY KEY,
  brand   TEXT NOT NULL,
  year    INT  NOT NULL
);

-- 创建子表（继承父表）
CREATE TABLE cars (
  doors INT NOT NULL DEFAULT 4
) INHERITS (vehicles);

CREATE TABLE trucks (
  payload_tons NUMERIC NOT NULL
) INHERITS (vehicles);

-- 查询父表时会包含所有子表数据
SELECT * FROM vehicles;          -- 返回 cars + trucks 的记录

-- 只查父表自身数据（不含子表）
SELECT * FROM ONLY vehicles;

-- 插入子表
INSERT INTO cars (brand, year, doors) VALUES ('Toyota', 2024, 4);
```

继承适合实现分区雏形或多态数据模型，但现代分区场景更推荐使用 `PARTITION BY` 声明式分区。

## 数据操作

### 插入数据（INSERT）

```sql
-- 单行插入
INSERT INTO app.users (username, email) VALUES ('alice', 'alice@example.com');

-- 多行插入
INSERT INTO app.users (username, email) VALUES
  ('bob',   'bob@example.com'),
  ('carol', 'carol@example.com');

-- 冲突时更新（UPSERT）
INSERT INTO app.users (username, email)
VALUES ('alice', 'new@example.com')
ON CONFLICT (username) DO UPDATE SET email = EXCLUDED.email;

-- 冲突时忽略
INSERT INTO app.users (username, email)
VALUES ('alice', 'new@example.com')
ON CONFLICT DO NOTHING;
```

### 查询数据（SELECT）

```sql
-- 基础查询
SELECT id, username, email FROM app.users WHERE status = 'active';

-- 排序与分页
SELECT * FROM app.users ORDER BY created_at DESC LIMIT 20 OFFSET 40;

-- 聚合
SELECT status, COUNT(*) AS cnt FROM app.users GROUP BY status HAVING COUNT(*) > 10;

-- 内连接
SELECT u.username, p.title
FROM app.users u
JOIN app.posts p ON p.user_id = u.id
WHERE u.status = 'active';

-- 左连接（保留左表无匹配行）
SELECT u.username, COUNT(p.id) AS post_cnt
FROM app.users u
LEFT JOIN app.posts p ON p.user_id = u.id
GROUP BY u.id;

-- 子查询
SELECT * FROM app.users
WHERE id IN (SELECT user_id FROM app.posts WHERE created_at > NOW() - INTERVAL '7 days');

-- CTE（公共表表达式，提升可读性）
WITH active_users AS (
  SELECT id, username FROM app.users WHERE status = 'active'
)
SELECT au.username, COUNT(p.id) AS post_cnt
FROM active_users au
LEFT JOIN app.posts p ON p.user_id = au.id
GROUP BY au.id, au.username;

-- 窗口函数（不折叠行）
SELECT username, score,
  RANK() OVER (ORDER BY score DESC) AS rank,
  AVG(score) OVER () AS avg_score
FROM app.users;
```

### 更新数据（UPDATE）

```sql
-- 条件更新
UPDATE app.users SET status = 'inactive' WHERE last_login < NOW() - INTERVAL '90 days';

-- 多列同时更新
UPDATE app.users SET status = 'vip', score = score + 100 WHERE id = 1;

-- 基于另一张表的值更新（UPDATE ... FROM）
UPDATE app.users u
SET score = u.score + p.bonus
FROM app.promotions p
WHERE p.user_id = u.id AND p.active = TRUE;

-- 返回被修改的行
UPDATE app.users SET status = 'vip' WHERE id = 1 RETURNING id, username, status;
```

### 删除数据（DELETE）

```sql
-- 条件删除
DELETE FROM app.users WHERE status = 'banned';

-- 基于另一张表的条件删除（DELETE ... USING）
DELETE FROM app.users u
USING app.ban_list b
WHERE b.user_id = u.id;

-- 返回被删除的行
DELETE FROM app.users WHERE id = 42 RETURNING *;
```

### 事务控制

```sql
-- 显式事务：要么全成功，要么全回滚
BEGIN;
  UPDATE app.accounts SET balance = balance - 100 WHERE id = 1;
  UPDATE app.accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;   -- 全部成功则提交

-- 出错时回滚
BEGIN;
  DELETE FROM app.orders WHERE user_id = 99;
ROLLBACK;  -- 撤销所有变更

-- 保存点（部分回滚）
BEGIN;
  INSERT INTO app.logs (msg) VALUES ('step1');
  SAVEPOINT sp1;
  INSERT INTO app.logs (msg) VALUES ('step2');
  ROLLBACK TO SAVEPOINT sp1;  -- 只撤销 step2
COMMIT;
```
